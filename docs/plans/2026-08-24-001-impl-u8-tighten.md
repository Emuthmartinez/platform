# U8 — Colombia backfill tighten (KTD6 steps 4-6)

Parent: [Multi-Incident Platform Migration](./2026-08-12-001-refactor-multi-incident-platform-plan.md).
Ledger: [2026-08-22 execution ledger](./2026-08-22-001-multi-incident-platform-execution-ledger.md).

This sub-plan does not weaken parent safety, tenancy, contract, cache, queue,
offline, migration, rollout, or rollback rules. It implements only the tighten
slice of U8 (R6, R7, KTD6 steps 4-6). Backfill (step 3) is already applied on
Colombia staging.

## Goal

Every incident-scoped table from the U8 backfill manifest has
`organization_id` and `incident_id` NOT NULL, validated composite FKs, and a
tenant-leading index. `audit_log` stays mixed-scope and is out of this slice.

## Non-negotiable choices (settled)

1. **Migrate-first.** Apply `0024_tenant_tighten.sql` on the target database
   before merging code that types the columns as required. Staging only for
   Colombia. Isolated Neon for the platform clone.
2. **Do not SET NOT NULL inside the transactional migrator on a hot table
   without a validated CHECK.** The ops runner adds and validates
   `{table}_organization_id_nn` / `{table}_incident_id_nn` and validates
   `{table}_incident_ownership_fk`. The journaled migration then
   `SET NOT NULL`, drops the temporary CHECKs, and creates
   `{table}_tenant_scope_idx` with `IF NOT EXISTS` (non-concurrent).
3. **Never `CREATE INDEX CONCURRENTLY` in `migrate.ts`.** The ops runner
   pre-creates that index. It refuses a same-name invalid or mismatched
   index unless `--replace-invalid-index` is set.
4. **Fail closed on leftover NULLs.** The ops runner refuses `apply` when
   any listed table still has NULL tenant columns.
5. **No production Neon. No Colombia `staging` → `main` merge.**
6. **No `audit_log` in this slice.**

## Procedure

1. Preflight: `ops:tighten --domain <d> --mode count-only`. Every
   `unscoped` value must be 0.
2. Apply: `ops:tighten --domain <d> --mode apply` on the Neon **direct**
   endpoint. One domain at a time.
3. Apply `0024_tenant_tighten.sql` with `backend/worker/migrate.ts`.
4. Merge this branch to Colombia `staging` and to platform `main`.
5. Record checksum, operator, and `information_schema.columns.is_nullable`
   in the execution ledger.

## Rollback

Columns stay NOT NULL. Rollback is a Worker/code revert that still stamps
tenant columns. Restoring nullability needs a new expand migration and is
not this slice.

## Out of scope

U10 scoped repositories, U34 Upstash, Queue v2 producers, `audit_log`
classifier, Colombia production Neon.
